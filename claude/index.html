Wiring .claude/ in a project

Claude Code looks for tooling in the .claude/ folder at the root of a project. The folder structure is: 

.claude/
├── settings.json          ← hooks, MCP servers, enabled features
├── settings.local.json    ← per-machine permission allowlists (gitignore this)
├── agents/                ← subagent definitions (.md files)
├── commands/              ← slash command definitions (.md files)
├── hooks/                 ← hook scripts (Python, shell, etc.)
└── skills/
    └── my-skill/
        └── SKILL.md       ← skill definition

settings.json structure

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit|Write|MultiEdit",
        "hooks": [
          {
            "type": "command",
            "command": "python3 .claude/hooks/security_reminder_hook.py"
          }
        ]
      }
    ]
  },
  "enabledMcpjsonServers": ["jira"]
}

settings.local.json — permission allowlist

Pre-approve common commands to reduce permission prompts. This file is machine-specific and should be gitignored: 

{
  "permissions": {
    "allow": [
      "Bash(npm run:*)",
      "Bash(npx prettier *)",
      "Bash(npx tsc *)",
      "Bash(eslint .)",
      "Bash(prettier --write .)",
      "Bash(gh api:*)",
      "Bash(git status:*)",
      "Bash(git diff:*)",
      "Bash(git log:*)"
    ]
  }
}

Agent files

Agent files in .claude/agents/ use YAML front matter:

---
name: my-agent
description: One-line description of when Claude Code should use this agent
model: sonnet
color: green
---

Agent system prompt here. Describe what the agent does, its process,
and what it outputs.

Command files

Command files in .claude/commands/ use YAML front matter:

---
description: What this command does
argument-hint: [optional-args]
allowed-tools:
  - Bash(git status:*)
  - Bash(git commit:*)
---

Command instructions here. Describe the exact steps Claude should follow
when the user runs /command-name.

Skill files

Skills live in .claude/skills/skill-name/SKILL.md and are invoked with /skill-name:

---
name: my-skill
description: When to use this skill
---

Skill instructions here.

Using this knowledge bank from a project

Add the knowledge bank as a submodule, then reference it from your project's CLAUDE.md or from agent/command files so Claude Code can navigate its documentation: 

git submodule add <remote-url> knowledge_bank

In your project's CLAUDE.md, point agents to the knowledge bank entry point: 

## Knowledge bank

Project-agnostic patterns and tooling are documented in `knowledge_bank/`.
Start from `knowledge_bank/index.html` and follow theme links to find relevant docs.
