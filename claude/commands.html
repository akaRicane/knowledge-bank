feature-dev

Guided feature development through 7 structured phases. Prioritizes understanding existing code before writing new code. Uses TodoWrite to track progress throughout. 

/feature-dev [optional feature description]

7-phase workflow

  1. Discovery — Create todo list. Ask clarifying questions if the feature is unclear. Summarize understanding and confirm with user.
  2. Codebase exploration — Launch 2–3 code-explorer agents in parallel (different aspects). Read all identified files. Present findings.
  3. Clarifying questions — Review findings, identify underspecified aspects, present all questions to user, wait for answers.
  4. Architecture design — Launch 2–3 code-architect agents with different focuses. Present summary, trade-offs, and recommendation. Ask user to pick an approach.
  5. Implementation — Wait for explicit approval. Read all relevant files. Implement. Update todos as work progresses.
  6. Quality review — Launch code-reviewer agents. Present findings. Ask what to fix.
  7. Summary — Mark todos complete. Summarize what was built, decisions made, files changed, and next steps.

review-pr

Runs specialized review agents against the current branch's changes. Can run all reviews or specific aspects. 

/review-pr [aspects]

# Examples:
/review-pr                   # all aspects (default)
/review-pr tests errors      # specific aspects
/review-pr code simplify     # two aspects

Output

Findings aggregated and organized by severity: Critical → Important → Suggestions → Strengths.

code-review

Reviews a GitHub PR using multi-agent validation. Designed to minimize false positives — only reports issues with high confidence that are not pre-existing. 

/code-review                  # review and display findings
/code-review --comment        # review and post inline GitHub comments

Workflow

  1. Check if PR is closed, draft, or already reviewed — stop if so.
  2. Collect all relevant CLAUDE.md files (root + directories with changed files).
  3. View PR and summarize changes.
  4. Launch 4 agents in parallel: 2× CLAUDE.md compliance audit (sonnet), 1× bug scan (opus), 1× security + logic (opus).
  5. For each high-signal issue, launch a validation subagent to confirm it's real.
  6. Filter to validated issues only.
  7. If --comment: post inline GitHub comments using suggestion blocks for small fixes.

High-signal criteria

  • Code will fail to compile or parse.
  • Code will definitely produce wrong results.
  • Clear, unambiguous CLAUDE.md violations.

Not reported

  • Pre-existing issues
  • Code style concerns
  • Issues that depend on specific inputs
  • Things a linter will catch
  • Issues silenced with lint-ignore

Required tools

gh pr view, gh pr diff, gh pr comment — GitHub CLI must be authenticated.

commit

Creates a git commit from current changes in a single operation.

/commit

What it does

  1. Show git status
  2. Show staged and unstaged changes (git diff HEAD)
  3. Show current branch and recent commits
  4. Create a single commit with an appropriate message

All steps execute in one message. Does not push.

Allowed tools

Bash(git add:*), Bash(git status:*), Bash(git commit:*)

commit-push-pr

Commits, pushes, and opens a GitHub PR in a single operation.

/commit-push-pr

What it does

  1. Show git status and diff
  2. Create a new branch if currently on main
  3. Create a commit with an appropriate message
  4. Push branch to origin with -u
  5. Create a PR via gh pr create

All steps execute in one message.

Allowed tools

Bash(git checkout --branch:*), Bash(git add:*), Bash(git status:*), Bash(git push:*), Bash(git commit:*), Bash(gh pr create:*)

clean_gone

Cleans up local git branches marked as [gone] — branches whose remote counterpart has been deleted (e.g. after a merged PR). Also removes associated worktrees. 

/clean_gone

What it does

  1. List branches with git branch -v to identify [gone] status.
  2. List worktrees with git worktree list.
  3. For each [gone] branch: remove the associated worktree (if any), then delete the local branch.
  4. Report what was removed.
