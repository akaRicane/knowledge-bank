Tuyau

Type-safe API client and Inertia routing layer for AdonisJS. Generates a typed registry from routes at build time, eliminating raw fetch() calls, manual CSRF headers, and hardcoded route strings. Package: @tuyau/core.

tuyau inertia type-safety api-client Last updated: 2026-05-17

Overview

Tuyau runs as an assembler hook that watches AdonisJS routes and generates a typed registry into .adonisjs/client/ on every change. The frontend imports this registry to create a client that knows the exact shape of every route — name, params, request body, and response type.

Two layers

LayerWhat it replacesEntry point
Inertia routing Hardcoded href strings in <Link> and router.visit() TuyauProvider, Link, useRouter, urlFor
API client Raw fetch() with manual CSRF headers and status checks client.api.routeName({ body, params, query })

Both layers share a single client instance created with createTuyau(). Built on Ky — fetch-based with automatic retries, timeout, and hook support.

Inertia v4 peer dependency

⚠
@adonisjs/inertia v4 declares @tuyau/core as a peer dependency. Its Link, useRouter, and useTuyau exports call useTuyau() internally on every render — even for plain href usage — and throw "You must wrap your app in a TuyauProvider" if the provider is absent. Install @tuyau/core and wire TuyauProvider before using any import from @adonisjs/inertia/react.

Until the provider is wired, a safe workaround is to import Link from @inertiajs/react directly (no Tuyau dependency). This is a behavioural drop-in for href-only usage.

Installation

npm install @tuyau/core

adonisrc.ts hook

The generateRegistry() assembler hook regenerates .adonisjs/client/registry/ on every route change. Add it to the init hooks array alongside the Inertia page indexer: 

// adonisrc.ts
import { defineConfig } from '@adonisjs/core/app'
import { indexPages } from '@adonisjs/inertia'
import { indexEntities } from '@adonisjs/core'
import { generateRegistry } from '@tuyau/core/hooks'

export default defineConfig({
  hooks: {
    init: [
      indexEntities({ transformers: { enabled: true, withSharedProps: true } }),
      indexPages({ framework: 'react' }),
      generateRegistry(),
    ],
    buildStarting: [() => import('@adonisjs/vite/build_hook')],
  },
})

Aliases (tsconfig + vite)

Expose the generated registry under the @generated/* alias in both TypeScript and Vite so imports are stable regardless of the output path. 

// inertia/tsconfig.json
{
  "extends": "@adonisjs/tsconfig/tsconfig.client.json",
  "compilerOptions": {
    "paths": {
      "~/*":          ["./*"],
      "@generated/*": ["../.adonisjs/client/*"]
    }
  },
  "include": ["./**/*.ts", "./**/*.tsx", "../.adonisjs/server/**/*"]
}
// vite.config.ts
export default defineConfig({
  resolve: {
    alias: {
      '~/':        `${import.meta.dirname}/inertia/`,
      '@generated': `${import.meta.dirname}/.adonisjs/client/`,
    },
  },
})

Client creation

Create a single shared instance. All components and API call files import from this one file — createTuyau is called exactly once. 

// inertia/client.ts
import { registry } from '@generated/registry'
import { createTuyau } from '@tuyau/core/client'

export const client = createTuyau({
  baseUrl: '/',
  registry,
  credentials: 'include',  // sends session + CSRF cookies automatically
})

export const urlFor = client.urlFor

Full options reference

export const client = createTuyau({
  baseUrl: 'http://localhost:3333',
  registry,
  credentials: 'include',
  timeout: 30_000,
  retry: {
    limit: 3,
    methods: ['get'],
    statusCodes: [408, 429, 502, 503, 504],
  },
  headers: { Accept: 'application/json' },
  hooks: {
    beforeRequest: [(req) => console.log('→', req.url)],
    afterResponse:  [(_, __, res) => console.log('←', res.status)],
    beforeError:    [(err) => { console.error(err.message); return err }],
  },
})

TuyauProvider

Wrap the Inertia app root in TuyauProvider so the client is available to all components via React context. 

// inertia/app/app.tsx
import { TuyauProvider } from '@adonisjs/inertia/react'
import { resolvePageComponent } from '@adonisjs/inertia/helpers'
import { createInertiaApp } from '@inertiajs/react'
import { createRoot } from 'react-dom/client'
import { client } from '~/client'

createInertiaApp({
  resolve: (name) =>
    resolvePageComponent(`../pages/${name}.tsx`, import.meta.glob('../pages/**/*.tsx')),

  setup({ el, App, props }) {
    createRoot(el).render(
      <TuyauProvider client={client}>
        <App {...props} />
      </TuyauProvider>
    )
  },
})

Inertia routing layer

Link component

Import Link from @adonisjs/inertia/react. Accepts either a typed route name or a plain href. When using href, the component delegates directly to the underlying @inertiajs/react Link with no route lookup. 

import { Link } from '@adonisjs/inertia/react'

// typed route name — TypeScript enforces name and params at compile time
<Link route="posts.index">All posts</Link>
<Link route="posts.show" routeParams={{ id: post.id }}>View post</Link>

// plain href — zero route resolution, same as @inertiajs/react Link
<Link href="/terms">Terms</Link>

useRouter

Programmatic navigation with the same typed API.

import { useRouter } from '@adonisjs/inertia/react'

const router = useRouter()

// typed route
router.visit({ route: 'posts.index' })
router.visit({ route: 'posts.show', routeParams: { id: '123' } })

// plain href (passes through to Inertia router)
router.visit({ href: '/dashboard' })

urlFor

Generate a URL string without navigating. Useful for <form action>, clipboard writes, or passing URLs as props. 

import { urlFor } from '~/client'

const indexUrl = urlFor('posts.index')
const showUrl  = urlFor('posts.show', { id: 42 })

// method-specific + query string
const filteredUrl = urlFor.get('posts.index', {}, { qs: { page: 2, status: 'published' } })

// wildcard
const docsUrl = urlFor.get('docs.show', { '*': ['intro', 'getting-started'] })

API call layer

Route name, request body, params, query string, and response type are all inferred from the registry — no manual type annotations needed.

Proxy syntax (recommended)

Route name segments map to chained property access. Underscores convert to camelCase: auth.reset_password → client.api.auth.resetPassword(). 

// auth.login → POST /auth/login
const result = await client.api.auth.login({
  body: { email, password },
})

// posts.store → POST /posts
const result = await client.api.posts.store({
  body: { title: 'Hello world', content: '...' },
})

// posts.show → GET /posts/:id
const result = await client.api.posts.show({
  params: { id: '123' },
})

Alternative: client.request('route.name', options) — identical behaviour, string-based.

Safe mode & error handling

Append .safe() to receive a [data, error] tuple instead of a thrown exception. The error object exposes typed status and validation helpers. 

const [data, error] = await client.api.auth.login({
  body: { email, password },
}).safe()

if (error) {
  if (error.isStatus(401)) {
    // invalid credentials
  }
  if (error.isValidationError()) {
    for (const e of error.response.errors) {
      console.log(e.field, e.message)
    }
  }
  if (error.kind === 'network') {
    console.error('Server unreachable')
  }
  return
}

// data is fully typed here
console.log(data.token)

Try/catch with explicit cast:

import type { Route } from '@tuyau/core/types'

try {
  await client.api.posts.show({ params: { id: '123' } })
} catch (e) {
  const error = e as Route.Error<'posts.show'>
  if (error.isStatus(404)) console.log('Not found')
}

Params & query

// route param + query string
const result = await client.api.posts.show({
  params: { id: '123' },
  query: { include: 'comments' },
})

// POST with param + body
const result = await client.api.posts.comments.store({
  params: { postId: '123' },
  body: { content: 'Great post!' },
})

// file upload
const result = await client.api.users.avatar.update({
  body: { avatar: file },   // File object — Tuyau handles multipart automatically
})

CSRF handling

When credentials: 'include' is set, Tuyau reads the XSRF-TOKEN cookie and injects the X-XSRF-TOKEN header automatically on every mutating request. No manual CSRF plumbing is needed.

Any helper that previously read the cookie from document.cookie and attached it as a fetch header can be deleted once the Tuyau client is in place. The @adonisjs/shield CSRF middleware on the server is unchanged — Tuyau only changes how the token is sent from the client.

ℹ
credentials: 'include' is the correct setting for session-based (cookie) auth. For token-based auth (Bearer header), omit it and instead inject the token via a beforeRequest hook.

Type extraction

Pull request/response/error types by route name for use in component props, service signatures, or test fixtures. 

import type { Route, Path } from '@tuyau/core/types'

// by route name
type StoreBody     = Route.Body<'posts.store'>
type StoreResponse = Route.Response<'posts.store'>
type ShowError     = Route.Error<'posts.show'>
type ShowParams    = Route.Params<'posts.show'>
type IndexQuery    = Route.Query<'posts.index'>

// by HTTP method + URL path
type LoginResponse = Path.Response<'POST', '/auth/login'>
type UserParams    = Path.Params<'GET', '/users/:id'>
ℹ
Dates serialize to strings. A DateTime column returned from the server appears as string in the inferred response type. Use @tuyau/superjson to preserve rich types (Luxon DateTime, BigInt, etc.) across the wire when needed.

Route filtering

Restrict the generated registry to avoid leaking internal or admin route names to the client bundle. 

// include only specific route groups
generateRegistry({
  routes: {
    only: ['auth.*', 'posts.*', 'navigations.*'],
  },
})

// or exclude by pattern
generateRegistry({
  routes: {
    except: [/^admin\./, (name) => name.startsWith('internal.')],
  },
})

Two-app monorepo pattern

In a monorepo with a separate backend API app and an Inertia webapp, each app can have its own Tuyau registry, and the webapp can use two clients:

  • Webapp client — points at the webapp's own routes (baseUrl: '/', session cookie auth, credentials: 'include'). Covers Inertia navigation and form submissions handled by the webapp's controllers.
  • Backend client — points at the REST API (baseUrl: import.meta.env.VITE_API_URL, token auth via Authorization: Bearer header). Covers data-fetching calls to the backend (entities, search, etc.).

Backend setup

// backend/adonisrc.ts — add generateRegistry to init hooks
hooks: {
  init: [
    indexEntities({ transformers: { enabled: true } }),
    generateRegistry(),
  ],
}
// backend/package.json — export the registry for the webapp to consume
{
  "exports": {
    "./registry": "./.adonisjs/client/registry/index.ts"
  }
}

Webapp backend client

// inertia/backend-client.ts
import { registry } from '@my-app/backend/registry'
import { createTuyau } from '@tuyau/core/client'

export const backendClient = createTuyau({
  baseUrl: import.meta.env.VITE_API_URL ?? 'http://localhost:3333',
  registry,
  headers: { Accept: 'application/json' },
  // no credentials: 'include' — backend uses token auth, not cookies
  hooks: {
    beforeRequest: [
      (req) => {
        const token = getAuthToken()   // read from cookie, store, or context
        if (token) req.headers.set('Authorization', `Bearer ${token}`)
      },
    ],
  },
})
⚠
The backend tsconfig in the webapp's frontend compilation unit must include the backend source files so the registry types resolve correctly. Add a ../backend/**/*.ts glob to inertia/tsconfig.json include and enable experimentalDecorators if the backend uses them.
