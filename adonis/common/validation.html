Validation

VineJS validators in AdonisJS. Defines schema, common rules, controller usage, and the error response shape.

adonis vinejs validation Last updated: 2026-05-14

Overview

AdonisJS uses VineJS for validation, registered via vinejs_provider in adonisrc.ts. Validators live in app/validators/, one file per domain (e.g., user_validator.ts).

Validation failures automatically return 422 Unprocessable Entity with a structured error body — no manual try/catch needed.

Defining validators

// app/validators/user_validator.ts
import vine from '@vinejs/vine'

export const createUserValidator = vine.compile(
  vine.object({
    email:           vine.string().email().normalizeEmail(),
    password:        vine.string().minLength(8),
    confirmPassword: vine.string().sameAs('password'),
  })
)

export const loginValidator = vine.compile(
  vine.object({
    email:    vine.string().email(),
    password: vine.string(),
  })
)

export const updateProfileValidator = vine.compile(
  vine.object({
    displayName: vine.string().maxLength(100).nullable().optional(),
    bio:         vine.string().maxLength(500).nullable().optional(),
    avatarUrl:   vine.string().url().nullable().optional(),
    city:        vine.string().nullable().optional(),
    country:     vine.string().nullable().optional(),
  })
)
ℹ
vine.compile() pre-compiles the schema for better performance. Always use it for validators that will be called repeatedly.

Common rules

RuleUsage
.email()Validate email format
.normalizeEmail()Lowercase and normalize the email
.minLength(n)String minimum length
.maxLength(n)String maximum length
.sameAs('field')Must match another field's value
.url()Validate URL format
.nullable()Allow null as a valid value
.optional()Field can be absent from the request
.range([min, max])Number within range (inclusive)
.enum(values)Must be one of the given values
.array(vine.string())Array of strings

nullable vs optional

  • .nullable() — field must be present but can be null.
  • .optional() — field can be absent entirely (undefined).
  • .nullable().optional() — field can be absent or null (partial update pattern).

Using in controllers

import { createUserValidator } from '#validators/user_validator'

// In a controller method:
async register({ request, response }: HttpContext) {
  // Throws and returns 422 automatically if validation fails
  const payload = await request.validateUsing(createUserValidator)

  // payload is fully typed based on the schema
  const user = await this.userService.create(payload)
  return response.created({ user })
}
ℹ
convertEmptyStringsToNull: true is set in config/bodyparser.ts. This means empty string inputs from forms are automatically converted to null before reaching validators — pair this with .nullable() on optional fields.

Error response shape

Validation failures return 422 with this structure:

{
  "errors": [
    {
      "field": "email",
      "rule": "email",
      "message": "The email field must be a valid email address"
    },
    {
      "field": "password",
      "rule": "minLength",
      "message": "The password field must have at least 8 characters"
    }
  ]
}

Test for validation errors by asserting response.status === 422 and inspecting response.body().errors.

Testing validators

Unit-test validators by calling validate() directly — no HTTP layer needed:

import { createUserValidator } from '#validators/user_validator'

test('valid data passes', async ({ assert }) => {
  const output = await createUserValidator.validate({
    email: 'user@example.com',
    password: 'secret123',
    confirmPassword: 'secret123',
  })
  assert.equal(output.email, 'user@example.com')
})

test('short password fails', async ({ assert }) => {
  await assert.rejects(
    () => createUserValidator.validate({
      email: 'user@example.com',
      password: 'short',
      confirmPassword: 'short',
    }),
    /minLength/
  )
})
