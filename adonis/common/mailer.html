Mailer

SMTP-based transactional email via @adonisjs/mail. Covers configuration, the MAILER_MOCK interception system, and test patterns.

adonis smtp testing Last updated: 2026-05-14

Package & registration

@adonisjs/mail ^9.2.2

Register in adonisrc.ts:

commands: [() => import('@adonisjs/mail/commands')],
providers: [() => import('@adonisjs/mail/mail_provider')],

Configuration

File: backend/config/mail.ts

import env from '#start/env'
import { defineConfig, transports } from '@adonisjs/mail'

const mailConfig = defineConfig({
  default: 'smtp',

  from: {
    address: env.get('MAIL_FROM_ADDRESS'),
    name:    env.get('MAIL_FROM_NAME'),
  },

  mailers: {
    smtp: transports.smtp({
      host:       env.get('MAIL_HOST'),
      port:       env.get('MAIL_PORT'),
      secure:     false,
      requireTLS: true,   // STARTTLS on port 587
      auth: {
        type: 'login',
        user: env.get('MAIL_USERNAME'),
        pass: env.get('MAIL_PASSWORD'),
      },
    }),
  },
})

export default mailConfig

declare module '@adonisjs/mail/types' {
  export interface MailersList extends InferMailers<typeof mailConfig> {}
}

Environment variables

All variables are required — no optional fallbacks. Defined in backend/start/env.ts.

VariableExampleDescription
MAIL_HOSTmail.example.comSMTP server hostname
MAIL_PORT587SMTP port (STARTTLS)
MAIL_USERNAMEadmin@example.comSMTP authentication account
MAIL_PASSWORD...Password for SMTP account
MAIL_FROM_ADDRESSapp@example.comFrom address shown to recipients
MAIL_FROM_NAMEMyAppDisplay name shown to recipients
MAILER_MOCKtrueIntercept all mail in tests (see below)

Alias pattern

Authenticate with one address (MAIL_USERNAME) but send from another (MAIL_FROM_ADDRESS). This is standard SMTP alias behaviour — the receiving server sees the From address, while the SMTP session uses the auth account.

dotenv special characters in passwords

SMTP passwords may contain # and $. Both require special handling:

  • # is treated as a comment delimiter — the value must be quoted.
  • $ is subject to variable interpolation inside double quotes — escape it as \$.
MAIL_PASSWORD="my#password\$with-special-chars"

Sending mail

import mail from '@adonisjs/mail/services/main'

// Callback-based (raw message)
await mail.send((message) => {
  message
    .to('user@example.com')
    .subject('Welcome')
    .html('<p>Hello!</p>')
})

// Class-based (recommended for complex mails with templates)
await mail.send(new WelcomeMail(user))

The global from address from config/mail.ts is applied automatically. Override per-message with .from() if needed.

MAILER_MOCK system

Without mocking, every test run that touches any auth flow would send real emails. MAILER_MOCK=true prevents this globally via a 3-layer interception system.

Layer 1 — Boot-time interception (start/mailer.ts)

import env from '#start/env'
import mail from '@adonisjs/mail/services/main'

if (env.get('MAILER_MOCK')) {
  mail.fake()
}

Runs at every app boot. Ensures the fake is active even when the server starts for webapp tests.

Layer 2 — Global teardown (tests/bootstrap.ts)

export const runnerHooks = {
  setup: [
    async () => {
      if (process.env.MAILER_MOCK === 'true') {
        mail.fake()  // harmless if already faked
      }
    },
  ],
  teardown: [
    async () => {
      mail.restore()  // reset transport after all tests
    },
  ],
}

Layer 3 — Per-test reset

test.group('My group', (group) => {
  let fake: ReturnType<typeof mail.fake>

  group.each.setup(() => {
    fake = mail.fake()  // new FakeMailer with empty message list
  })

  test('sends a welcome email', async () => {
    // ... trigger code that sends email ...
    fake.messages.assertSent({ to: 'user@example.com', subject: 'Welcome' })
  })
})

Calling mail.fake() inside a test group returns a fresh FakeMailer instance with an empty messages list, giving each test a clean slate.

Full mock flow

MAILER_MOCK=true
      │
      ▼
start/mailer.ts → mail.fake()          ← active at boot, any context
      │
      ▼
bootstrap setup → mail.fake()          ← re-faked (no-op)
      │
      ▼
group.each.setup → fake = mail.fake()  ← new FakeMailer, clean slate
      │
      ▼
test → mail.send(...)                  ← captured, not sent
      │
      ▼
assertion → fake.messages.assertSent()
      │
      ▼
bootstrap teardown → mail.restore()    ← real transport restored

Smoke test (real SMTP)

Create a separate test group that skips when MAILER_MOCK=true. This allows verifying the live SMTP connection without it running on every CI pass: 

test.group('Mailer - real SMTP (smoke)', () => {
  test('sends a real email', async ({ assert }) => {
    if (process.env.MAILER_MOCK === 'true') {
      assert.isTrue(true, 'Skipped: MAILER_MOCK=true')
      return
    }
    await mail.send((message) => {
      message.to('your@email.com').subject('Smoke test').html('OK')
    })
  }).tags(['smoke'])
})
