Authentication

Token-based auth on the backend (OAT via @adonisjs/auth), and cookie-based token forwarding on the webapp. Covers the full user lifecycle: register, login, email verification, password reset, roles.

adonis auth oat Last updated: 2026-05-14

Backend — OAT Guard

The backend uses Opaque Access Tokens (OAT) via the authToken guard. Tokens are stored in the auth_access_tokens database table.

Guard configuration

File: backend/config/auth.ts

default: 'authToken',
guards: {
  authToken: tokensGuard({
    provider: tokensUserProvider({
      tokens: 'accessTokens',
      model: () => import('#models/user'),
    }),
  }),
}

The User model exposes static accessTokens = DbAccessTokensProvider.forModel(User) for token storage.

Registration

Endpoint: POST /user/register (public)

  1. Validate with createUserValidator — email, password, confirmPassword (min 8 chars, must match).
  2. Check for duplicate email via UserService.alreadyExists() → 409 if found.
  3. UserService.create() runs a DB transaction: creates User with a random 64-char emailVerificationToken, then creates linked Profile.
  4. Generate access token via UserService.generateToken().
  5. Send VerifyEmailMail.
  6. Return 201 with { user, token, message }.
{
  "user": { "publicId": "...", "email": "...", "profile": { ... } },
  "token": { "type": "bearer", "value": "oat_..." },
  "message": "Successfully registered user"
}

Login / Logout

Login: POST /user/login — validates credentials, calls User.verifyCredentials(), creates a new access token, returns { user, token }.

Logout: POST /user/logout (guarded) — deletes the current token via User.accessTokens.delete().

Update password: POST /user/update (guarded) — validates newPassword + confirmNewPassword. Password is auto-hashed by AuthFinder.

Delete account: DELETE /user/remove (guarded) — requires email + password re-authentication. Profile cascades on delete.

Email verification

Verify: GET /user/verify-email?token=... — looks up user by emailVerificationToken. Sets emailIsVerified = true and clears the token. Returns 400 if not found or already used.

Resend: POST /user/resend-verification (guarded) — generates a new 64-char token, sends VerifyEmailMail. Returns early if already verified.

Password reset

Request: POST /user/forgot-password — always returns 200 regardless of whether the email exists (prevents email enumeration). If user is found: generates a 64-char passwordResetToken with 1-hour expiry, sends PasswordResetMail.

Execute: POST /user/reset-password — validates token, password, confirmPassword. Returns 400 if token not found or expired. Clears token and expiry on success.

Roles & authorization

Enum file: backend/app/common/users/enums.ts

export enum UserRole {
  ADMIN     = 'admin',
  MODERATOR = 'moderator',
  DEFAULT   = 'default',
}

Stored as a PostgreSQL user_role enum type. Default: 'default'.

MethodReturns true when
user.isAdmin()role === ADMIN
user.isModerator()role === MODERATOR
user.hasModeratorAccess()role is ADMIN or MODERATOR

Currently only POST /users/index is role-gated (admin only, returns 401 for others).

Webapp — Cookie forwarding

The webapp does not use an AdonisJS auth guard. Instead it stores the backend OAT in an oat_token httpOnly cookie and forwards it as a Bearer header on every authenticated backend request.

ConcernMechanism
Token storageoat_token cookie (httpOnly, sameSite: lax, maxAge: 2h)
Token forwardingAuthorization: Bearer <token> header on backend requests
SessionAdonisJS cookie session (SESSION_DRIVER=cookie)
CSRF@adonisjs/shield — exempt for all /user/* routes

Cookie lifecycle

Set on register / login: on a successful backend response, the webapp sets the cookie:

ok
  ? response.cookie('oat_token', data.token.value as string)
  : response.clearCookie('oat_token')

Read on authenticated requests:

const authToken: string = request.cookie('oat_token', 'invalid_oat_token')

Cleared on logout / error: logout calls the backend to revoke the token, then response.clearCookie('oat_token').

Account page guard

The webapp has no auth middleware. NavigationsController.account manually checks the cookie:

async account(ctx: HttpContext) {
  const authToken = ctx.request.cookie('oat_token', 'invalid_oat_token')
  if (authToken) {
    const { data, ok } = await this.authService.getUser(authToken)
    if (!ok) return ctx.response.redirect('login')
    return ctx.inertia.render('account/Account', { user: data.user })
  } else {
    return ctx.response.redirect('login')
  }
}

CSRF exemption

All /user/* routes are exempt from CSRF verification in config/shield.ts:

csrf: {
  enabled: true,
  exceptRoutes: (ctx) => ctx.request.url().startsWith('/user'),
  enableXsrfCookie: true,
}

This allows client-side React to POST auth routes without managing X-XSRF-TOKEN headers.

Password hashing
