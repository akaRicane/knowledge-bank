adonisrc.ts structure

The adonisrc.ts file is the app definition. It declares providers, commands, preloads, test suites, and experimental flags. It replaces the v5 .adonisrc.json.

Providers

All providers use lazy imports — the function is called only if the provider is actually loaded.

// backend/adonisrc.ts
import { defineConfig } from '@adonisjs/core/app'

export default defineConfig({
  providers: [
    () => import('@adonisjs/core/providers/app_provider'),
    () => import('@adonisjs/core/providers/hash_provider'),
    [() => import('@adonisjs/core/providers/repl_provider'), ['repl', 'test']],
    () => import('@adonisjs/core/providers/vinejs_provider'),
    () => import('@adonisjs/cors/cors_provider'),
    () => import('@adonisjs/auth/auth_provider'),
    () => import('@adonisjs/lucid/database_provider'),
    () => import('@adonisjs/mail/mail_provider'),
  ],
})

The tuple syntax [provider, environments] restricts a provider to specific environments (e.g. repl_provider in repl and test only).

Preloads

preloads: [
  () => import('#start/routes'),
  () => import('#start/kernel'),
  () => import('#start/mailer'),  // boot-time mailer mock
],

Preloads run on every app boot, in order. Use them for one-time setup (routes, middleware, global mocks).

Experimental flags

experimental: {
  mergeMultipartFieldsAndFiles: true,  // multipart body + files merged into request.body()
  shutdownInReverseOrder: true,        // providers shut down LIFO
},

Test suites

tests: {
  suites: [
    {
      name: 'unit',
      files: ['tests/unit/**/*.spec(.ts|.js)'],
      timeout: 2000,
    },
    {
      name: 'functional',
      files: ['tests/functional/**/*.spec(.ts|.js)'],
      timeout: 30000,
    },
  ],
  forceExit: false,
},

Path aliases (#)

In v6, the # prefix replaces relative imports for app-internal paths. Aliases are declared in package.json under imports: 

{
  "imports": {
    "#controllers/*": "./app/controllers/*.js",
    "#models/*":      "./app/models/*.js",
    "#services/*":    "./app/services/*.js",
    "#validators/*":  "./app/validators/*.js",
    "#common/*":      "./app/common/*.js",
    "#start/*":       "./start/*.js",
    "#config/*":      "./config/*.js"
  }
}
ℹ
The .js extension is used even in TypeScript source because Node.js ESM resolves compiled output. TypeScript follows these mappings via tsconfig.json paths.

Middleware kernel

File: start/kernel.ts

import router from '@adonisjs/core/services/router'
import server from '@adonisjs/core/services/server'

// Server middleware — runs on every request
server.use([
  () => import('#middleware/container_bindings_middleware'),
  () => import('@adonisjs/cors/cors_middleware'),
  // webapp only:
  () => import('@adonisjs/static/static_middleware'),
  () => import('@adonisjs/vite/vite_middleware'),
  () => import('@adonisjs/inertia/inertia_middleware'),
])

// Router middleware — runs on matched routes
router.use([
  () => import('@adonisjs/core/bodyparser_middleware'),
  () => import('@adonisjs/auth/initialize_auth_middleware'),
  // webapp only:
  () => import('@adonisjs/session/session_middleware'),
  () => import('@adonisjs/shield/shield_middleware'),
])

// Named middleware
export const middleware = router.named({
  auth: () => import('#middleware/auth_middleware'),
})

Two-app monorepo setup

When running two AdonisJS apps in one monorepo:

  • Place each app in its own directory (backend/, webapp/).
  • Use a root package.json with workspace scripts to start both via concurrently.
  • Use wait-on to health-check the backend before running webapp tests.
  • Each app has its own tsconfig.json, adonisrc.ts, .env, and migrations.
  • The webapp reads BACKEND_API_URL to locate the backend at runtime.
// root package.json scripts
{
  "scripts": {
    "dev":          "concurrently \"npm run dev --workspace=backend\" \"npm run dev --workspace=webapp\"",
    "test":         "npm run test --workspace=backend && npm run seed && npm run test:webapp",
    "test:webapp":  "wait-on http://localhost:3333 && npm run test --workspace=webapp",
    "seed":         "npm run db:seed --workspace=backend"
  }
}

Env validation at boot

In v6, environment variables are validated at startup via start/env.ts. Missing or wrong-type values throw a fatal error before the server starts. 

// start/env.ts
import { Env } from '@adonisjs/core/env'

export default await Env.create(new URL('../', import.meta.url), {
  NODE_ENV: Env.schema.enum(['development', 'production', 'test'] as const),
  PORT:     Env.schema.number(),
  HOST:     Env.schema.string({ format: 'host' }),
  APP_KEY:  Env.schema.string(),
  DB_HOST:  Env.schema.string({ format: 'host' }),
  DB_PORT:  Env.schema.number(),
  DB_USER:  Env.schema.string(),
  DB_PASSWORD: Env.schema.string.optional(),
  DB_DATABASE: Env.schema.string(),
  MAILER_MOCK: Env.schema.boolean(),
})

There is no optional fallback for required variables — a missing value is always a boot error. This surfaces configuration issues early, before requests are accepted.

Useful ace commands

# Generate a new app key
node ace generate:key

# Run migrations
node ace migration:run
node ace migration:rollback

# Run seeders
node ace db:seed
node ace db:seed --files="database/seeders/main_seeder.ts"

# Create a migration
node ace make:migration create_artists_table

# Create a model
node ace make:model Artist

# Create a controller
node ace make:controller ArtistsController

# Run tests
node ace test
node ace test --suite=functional
node ace test -- --grep "pattern"

# Start dev server
node ace serve --watch
