AdonisJS v7

Version-specific notes: package versions, breaking changes from v6, adonisrc.ts restructure, Inertia v4 migration, and new conventions. Released February 25, 2026.

System requirements

⚠
Node.js 24+ is required. v7 will not boot on Node.js 22 or earlier. Update all environments — local, CI, and production — before upgrading.
  • Node.js: 24 LTS or later (nvm install --lts && nvm use --lts)
  • TypeScript: 5.8+ (6.x supported but optional)
  • ESLint: 10.x (if using @adonisjs/eslint-config)

adonisrc.ts changes

Hooks restructure

v7 introduces a mandatory init hooks array and renames the build hook. The assetsBundler property is removed entirely. 

// v6
export default defineConfig({
  assetsBundler: false,
  hooks: {
    onBuildStarting: [() => import('@adonisjs/vite/build_hook')],
  },
  experimental: {
    mergeMultipartFieldsAndFiles: true,
    shutdownInReverseOrder: true,
  },
})
// v7
export default defineConfig({
  // assetsBundler removed entirely
  init: [
    () => import('@adonisjs/core/initialize/http_server_provider'),
    () => import('@adonisjs/lucid/initialize/index_entities'),   // if using Lucid
    () => import('@adonisjs/inertia/initialize/index_pages'),    // if using Inertia
  ],
  hooks: {
    buildStarting: [() => import('@adonisjs/vite/build_hook')],  // renamed from onBuildStarting
  },
  // experimental flags are now defaults — remove them
})
ℹ
The experimental.mergeMultipartFieldsAndFiles and experimental.shutdownInReverseOrder flags are now default behaviour. Remove them from adonisrc.ts.

Test glob pattern

The file glob syntax for test suites changed.

// v6
files: ['tests/unit/**/*.spec(.ts|.js)']
// v7
files: ['tests/unit/**/*.spec.{ts,js}']

ts-node → ts-exec

ts-node-maintained is no longer used. Replace it with @poppinss/ts-exec in ace.js (the CLI entry point). 

// v6 — ace.js
import { register } from 'ts-node-maintained/register/esm'
register()
// v7 — ace.js
import { register } from '@poppinss/ts-exec'
register()

Remove ts-node-maintained from devDependencies and add @poppinss/ts-exec. Also add youch as a dev dependency for the new error page renderer.

Add the generated barrel file alias to package.json imports: 

{
  "imports": {
    "#generated/*": "./.adonisjs/server/*.js"
  }
}

Encryption config

v7 uses a driver-based encryption system. appKey in config/app.ts is now only used for HTTP cookies. A new config/encryption.ts is required for all other encryption (tokens, signed URLs, etc.). 

// config/encryption.ts
import env from '#start/env'
import { defineConfig, drivers } from '@adonisjs/core/encryption'

export default defineConfig({
  default: 'aes256cbc',
  drivers: {
    aes256cbc: drivers.aes256cbc({
      secret: env.get('APP_KEY'),
    }),
  },
})
⚠
If the app stored encrypted data with the v6 appKey (e.g. access tokens, signed URLs), add a legacy driver entry alongside the new one so existing data can still be decrypted. Consult the official upgrade guide for the legacy driver configuration.

Inertia v4 changes

This is the highest-impact change in a v7 migration for apps using Inertia. Several things must change together — middleware, config, file structure, and tsconfig.

Tuyau peer dependency (new in v4)

@adonisjs/inertia v4 introduces @tuyau/core as a peer dependency. The React exports (Link, useRouter, useTuyau, TuyauProvider) all depend on a Tuyau client being provided via context. Without it, any component that imports from @adonisjs/inertia/react throws at runtime: "You must wrap your app in a TuyauProvider".

Install the package and wire the provider in the Inertia app entry point: 

npm install @tuyau/core
// inertia/app/app.tsx
import { TuyauProvider } from '@adonisjs/inertia/react'
import { client } from '~/client'   // see Tuyau doc for client creation

setup({ el, App, props }) {
  createRoot(el).render(
    <TuyauProvider client={client}>
      <App {...props} />
    </TuyauProvider>
  )
}

See Tuyau for the full setup: generateRegistry() hook, alias configuration, client creation, typed Link, and API call patterns.

✦
Short-term workaround if deferring Tuyau setup: import Link from @inertiajs/react instead of @adonisjs/inertia/react. Behaviorally identical for href-based usage; no provider required. Revert to @adonisjs/inertia/react once the provider is wired.

Custom InertiaMiddleware

The direct use of @adonisjs/inertia/inertia_middleware is replaced by a custom class extending BaseInertiaMiddleware. This is where shared props (previously in config/inertia.ts as sharedData) now live. 

// v6 — start/kernel.ts
server.use([
  () => import('@adonisjs/inertia/inertia_middleware'),
])
// v7 — app/middleware/inertia_middleware.ts
import { BaseInertiaMiddleware } from '@adonisjs/inertia'
import type { HttpContext } from '@adonisjs/core/http'

export default class InertiaMiddleware extends BaseInertiaMiddleware {
  async share(ctx: HttpContext) {
    return {
      // shared props go here — replaces sharedData in config/inertia.ts
    }
  }
}

// v7 — start/kernel.ts
server.use([
  () => import('#middleware/inertia_middleware'),
])

File structure

The Inertia client entry point moves up one directory.

inertia/
└── app/
    ├── app.tsx        ← client entry point
    └── ssr.tsx
inertia/
├── app.tsx            ← moved from inertia/app/app.tsx
└── ssr.tsx

Update all imports that reference inertia/app/app.tsx after the move.

Config cleanup

Several properties are removed from config/inertia.ts in v4.

// v6 — config/inertia.ts
export default defineConfig({
  rootView: 'inertia_layout',
  sharedData: {
    errors: (ctx) => ctx.session?.flashMessages.get('errors'),
  },
  ssr: {
    enabled: false,
    entrypoint: 'inertia/app/ssr.tsx',
  },
})
// v7 — config/inertia.ts
export default defineConfig({
  rootView: 'inertia_layout',
  // sharedData removed → move to InertiaMiddleware.share()
  // ssr.entrypoint removed
  ssr: {
    enabled: false,
  },
})

Also: inertia.location() is now synchronous — remove any await before calls to it.

tsconfig.inertia.json

A new composite tsconfig is required at the webapp root to avoid circular references between the server and client TypeScript compilation units. 

// tsconfig.inertia.json (at webapp root)
{
  "extends": "@adonisjs/tsconfig/tsconfig.client.json",
  "compilerOptions": {
    "composite": true,
    "outDir": "./inertia_compiled",
    "rootDir": "./inertia"
  },
  "include": ["inertia/**/*"]
}

The main tsconfig.json should reference it: 

{
  "references": [{ "path": "./tsconfig.inertia.json" }]
}

Other package changes

Auth v10 — withAuthFinder signature

The hash manager is now passed as the first argument.

// v6
const MyModel = compose(
  BaseModel,
  withAuthFinder(() => hash.use('scrypt'), {
    uids: ['email'],
    passwordColumnName: 'password',
  })
)
// v7 — hash manager first, options second (same shape, verify arg order)
const MyModel = compose(
  BaseModel,
  withAuthFinder(hash, {
    uids: ['email'],
    passwordColumnName: 'password',
    hashDriver: 'scrypt',
  })
)

Session v8 — flash key rename

The errors flash key is renamed to inputErrors. Audit any templates or components reading flash messages. 

ctx.session.flashMessages.get('errors')
ctx.session.flashMessages.get('inputErrors')

Shield v9 — CSP implementation

helmet-csp is removed. CSP is now built-in. If config/shield.ts configures CSP directives, verify the key names match the new built-in shape (typically identical, but check the v9 release notes for any renamed directives).

Vite v5 — stale manifest

Vite v5 throws when the dev server is active but a production manifest exists on disk. Run node ace build --clean before switching back to dev mode if a previous build exists.

Lucid v22 — no breaking changes for existing models

Existing models using @column(), @hasOne(), etc. continue to work without changes. v22 adds opt-in Schema classes (auto-generated from migrations) and a new Transformer pattern — both additive.

HTTP type renames

Request and Response type imports from @adonisjs/core/http are renamed to HttpRequest and HttpResponse. Update any module augmentation or type-only imports. 

import type { Request } from '@adonisjs/core/http'
import type { HttpRequest } from '@adonisjs/core/http'

New conventions in v7

  • Barrel files — auto-generated at .adonisjs/server/ via the indexEntities() init hook. These replace manual module registration for models, validators, and services. Add #generated/* to package.json imports.
  • Type-safe routes — urlFor() from @adonisjs/core/services/url_builder replaces router.makeUrl(). Enforces named route parameters at compile time.
  • Transformers — new BaseTransformer pattern for serialising API responses. Replaces returning Lucid model instances directly. Opt-in and not required for migration.
  • Auto-named routes — routes registered with a controller method automatically receive a name (controller.method). Boot-time conflict detection catches duplicate names.
  • Type-safe inertia.render() — TypeScript enforces that props passed to inertia.render() match what the React component declares. Surfaced as compile errors, not runtime errors.
  • OpenTelemetry — zero-config via the new @adonisjs/otel package. Optional.
  • Tuyau — @tuyau/core is now a peer dependency of @adonisjs/inertia v4. Generates a typed route registry at build time, enabling type-safe navigation (Link, useRouter) and type-safe API calls (client.api.route.name()) from the React frontend. See Tuyau.

Migration guide

✦
An official upgrade guide is available at docs.adonisjs.com/v6-to-v7. A community automation tool, adonis-v7-easy-migration, handles many of the mechanical renames (hook names, utility replacements, Inertia file moves) and generates a diff report. Run it first, then apply the manual steps.

Recommended order

  1. Update Node.js to 24 LTS in all environments (local, CI, production).
  2. Optionally run adonis-v7-easy-migration for automated renames.
  3. Bump all @adonisjs/* and @japa/* packages.
  4. Replace ts-node-maintained with @poppinss/ts-exec in ace.js.
  5. Update adonisrc.ts: add init array, rename hooks, fix test glob, remove experimental flags.
  6. Create config/encryption.ts.
  7. Migrate Inertia: move entry file, create custom middleware, clean up config, add composite tsconfig.
  8. Run tsc --noEmit — fix any type errors surfaced by stricter Inertia render types.
  9. Run the full test suite.
